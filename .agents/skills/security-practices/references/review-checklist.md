# Security Review Checklist

A checklist for reviewing a change, ordered by severity. Each line points to the
rule that explains it; review the lines that the change touches.

---

## Critical

- [ ] No secret, key or password in code, configuration, fixtures, logs or
      error answers (security-rules.md: Secrets Come From the Environment)
- [ ] No content, personal data, session ID or token in logs, audit records or
      telemetry (security-rules.md: Secrets and Personal Data Never Reach
      Output)
- [ ] SQL goes through sqlc placeholders; commands take an argument array; no
      `sh -c` with input; no user text in `dangerouslySetInnerHTML`
      (security-rules.md: No Injection Through Strings)
- [ ] No `encoding/gob`, `eval` or `new Function` on untrusted input
      (crypto-and-files.md: Decoding Untrusted Formats)
- [ ] A new table or personal column is in both the export datasets and the
      deletion steps (AGENTS.md: Privacy (export, hide, delete))

## High

- [ ] Every protected route runs behind `AuthMiddleware` and the service checks
      the permission for the resource; no error path allows (security-rules.md:
      Authorization in the Handler)
- [ ] Tokens: signing method pinned, secret required with no default, expiry
      checked, one refusal for every cause (http-and-auth.md: Tokens and
      Credentials)
- [ ] Identity comes from the session, not a header or a body field
      (http-and-auth.md: Client Identity Comes From the Server)
- [ ] Outbound requests to a supplied URL go through `lib.ValidateExternalURL`
      and refuse or re-check redirects (security-rules.md: Outbound Requests to
      User-Supplied URLs)
- [ ] Secrets and one-time codes come from `crypto/rand` or
      `crypto.getRandomValues` (security-rules.md: Secure Randomness)
- [ ] TLS 1.2 or newer, never `InsecureSkipVerify` (crypto-and-files.md: Use
      Vetted Primitives)
- [ ] Model output is validated and escaped like user content; MCP tools return
      only what an anonymous caller may read (security-rules.md: LLM Trust
      Boundary)
- [ ] `govulncheck` reports nothing reachable for a change to `go.mod`

## Medium

- [ ] Input bounded and validated at the boundary (security-rules.md: Input
      Validation)
- [ ] Body limit, rate limit and server timeouts apply to the listener
      (http-and-auth.md: Layered Controls)
- [ ] Answers carry a code or a fixed message, never Go error text
      (security-rules.md: Error Sanitization)
- [ ] A relaxation is an explicit setting with a safe default
      (security-rules.md: Safe Defaults and Explicit Outcomes)
- [ ] Session cookies `HttpOnly` and `Secure`; a state-changing endpoint is not
      reachable by a cross-site form post (http-and-auth.md: Cookies and CSRF)
- [ ] CORS allows exact origins only (http-and-auth.md: CORS)
- [ ] Redirect targets relative or exactly allowlisted (http-and-auth.md:
      Redirects and Debug Endpoints)
- [ ] Upload content types allowlisted, storage keys generated by the server,
      decoded and decompressed sizes bounded (crypto-and-files.md: Files From
      Untrusted Sources)
- [ ] Personal data is not stored as a plain hash (crypto-and-files.md: Hashing
      Personal Data)
- [ ] Tests cover the denial paths and assert that a content sentinel stays out
      of the output (qa-practices: What to Test)

## Low

- [ ] Security headers registered on the listener
      (http-and-auth.md: Security Headers)
- [ ] File permissions no wider than 0600 and 0700 (crypto-and-files.md: Files
      From Untrusted Sources)
- [ ] Production checklist walked for a deployment change (security-rules.md:
      Production Deployment Checklist)
