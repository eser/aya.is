## Use Vetted Primitives

Scope: Encryption, hashing, signatures, key derivation and TLS

Rule: Use the Go standard library or `golang.org/x/crypto`, and the building
blocks the repository already has (`golang-jwt` for tokens, `pkg/ajan/lib` for
random bytes), before writing a new one. Never write a cipher, a mode or a
token format by hand. Pick by purpose:

| Purpose | Use | Never |
| --- | --- | --- |
| Encrypting stored data | AES-256-GCM from the standard library, a key from the environment, a random nonce per encryption | ECB, a key used directly without derivation, a hand-made format |
| Password storage | Argon2id (http-and-auth.md: Passwords) | MD5, SHA-1, plain SHA-256 |
| Stored credential secrets | SHA-256 of a random 32-byte secret, compared in constant time | storing the secret, `==` on hashes |
| Message authentication | HMAC-SHA256, checked with `hmac.Equal` or `subtle.ConstantTimeCompare` | HMAC-MD5, `==` on MACs |
| Signatures | Ed25519, ECDSA P-256, RSA of at least 2048 bits | RSA under 2048 bits |
| Key derivation | `crypto/hkdf` with a purpose label per derived key | a bare hash of the secret |
| TLS | 1.2 minimum for serving | `MinVersion` below 1.2 |

- A GCM nonce is random per encryption; never a counter or a constant.
- `InsecureSkipVerify` is never set on a TLS configuration. The one place that
  exposes it is the Redis connection setting (`TLSInsecureSkipVerify` in
  `pkg/ajan/connfx`), which stays false (its zero value) in production.
- A self-signed certificate (`self_signed`, `GenerateSelfSignedCert` in
  `pkg/ajan/lib/crypto.go`) is for development only.
- An encryption or signing error fails the operation. Continuing with
  plaintext after a failed seal leaks data by design.

**Why:** a primitive chosen for the wrong purpose (a fast hash for passwords,
a MAC compared with `==`) fails as badly as a broken one, and reviewers catch
it more easily against a fixed table.

## Hashing Personal Data

Scope: Identities in events, counters, rate-limit keys and exports

Rule: A plain hash of an email address, a name or an IP address is not
anonymous: the input space is small enough to reverse by guessing. Store an
internal ID, or a keyed hash (HMAC with a server-side secret), or nothing;
never an email, a name or a plain hash of one. A stored hash of an IP address
counts as personal data and follows the same deletion rules (AGENTS.md: Privacy
(export, hide, delete)).

Correct:

```go
mac := hmac.New(sha256.New, secretKey)
mac.Write([]byte(ip))
key := hex.EncodeToString(mac.Sum(nil)) // useless without the server secret
```

Incorrect:

```go
hash := sha256.Sum256([]byte(ip)) // the whole IPv4 space can be hashed in seconds
```

**Why:** an unkeyed hash of a small input is a lookup table waiting to be built.

## Files From Untrusted Sources

Scope: Uploads, archives, documents, request bodies and paths from settings or
input

Rule:

- Uploads go to object storage through a presigned URL that the server issues
  after checking the purpose and the content type against an allowlist
  (`allowedContentTypes` in `pkg/api/business/uploads/service.go`). The storage
  key is generated by the server (purpose, user ID, timestamp, random part),
  never taken from the file name; derive the extension from the allowed content
  type, not from the name the client sent.
- Bound the size of an upload and of anything read from one: set a maximum in
  the presigned request or the bucket policy, and read bodies through
  `io.LimitReader` or `http.MaxBytesReader`.
- SVG is active content (scripts, external references). Accept it only for a
  purpose that needs it, and serve it from a separate origin or with a header
  that blocks script execution (`Content-Security-Policy: sandbox`), or
  sanitize it; raster formats are the default.
- Confine a path from input to a root with `os.OpenRoot` and its methods.
- Bound decoded and decompressed size, not only the encoded size: an archive is
  checked for entry count, per-entry and total expanded size and compression
  ratio before it is read.
- Write protected state atomically: `os.CreateTemp` in the target directory,
  `Chmod`, `Sync`, then rename. Permissions are 0600 for files with keys,
  tokens or state and 0700 for their directories; never 0666 or 0777.
- A file read for a secret is a regular file, not a symlink, bounded in size and
  not readable by group or others.
- Exports and other private downloads live in a private bucket and are handed
  out through short-lived presigned URLs, never a public URL (AGENTS.md:
  Privacy (export, hide, delete)).

Correct:

```go
allowedTypes, ok := allowedContentTypes[req.Purpose]
if !ok {
    return nil, ErrInvalidPurpose
}
if !isAllowedContentType(req.ContentType, allowedTypes) {
    return nil, ErrInvalidContentType
}
```

```go
root, err := os.OpenRoot(dir)
if err != nil {
    return fmt.Errorf("open upload directory: %w", err)
}
defer root.Close()
content, err := root.ReadFile(name) // a ".." or a symlink cannot leave dir
```

Incorrect:

```go
content, err := os.ReadFile(filepath.Join(dir, filepath.Clean(name))) // a symlink or ".." escapes
```

**Why:** attacker-chosen names, types and sizes become file system and storage
operations; confinement, allowlists and limits are the checks that do not
depend on predicting every malicious input.

## Decoding Untrusted Formats

Scope: JSON, XML, YAML and other decoders fed external input

Rule:

- Bound the input first, then decode into a concrete type, never `any`, and
  validate the result (security-rules.md: Input Validation).
- Never decode untrusted input with `encoding/gob`.
- `encoding/xml` does not expand external entities; still bound tokens and
  depth.
- Sizes and counts read from input (a length prefix, a row count) are checked
  against a maximum before allocating.
- In TypeScript, `JSON.parse` results are `unknown` until a zod schema has
  parsed them; never `eval` or `new Function` a string from input
  (coding-practices: No Runtime Code Generation or Global Patching).

Correct:

```go
data, err := io.ReadAll(io.LimitReader(resp.Body, maxResponseBytes+1))
if err != nil || len(data) > maxResponseBytes {
    return ErrResponseTooLarge
}

var payload Payload
if err := json.Unmarshal(data, &payload); err != nil {
    return fmt.Errorf("decode response: %w", err)
}
```

Incorrect:

```go
var payload any
_ = json.NewDecoder(resp.Body).Decode(&payload) // unbounded, untyped, error ignored
```

**Why:** a decoder given unbounded or untyped input spends memory on what an
attacker sends and hands the code values it did not expect.
